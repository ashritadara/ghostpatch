# Frontend interaction updates

- Expandable analysis, Memory, Signals, Trials, test, activity, repair, diff, and error cards open a live React side inspector in the existing iframe. No evidence is copied into static HTML.
- The inspector occupies the right half of the workspace, with its own vertical scroll. Narrow screens use the full workspace width. Close or Escape restores focus; changing chapters dismisses it. Nested evidence can expand inside the inspector.
- Evidence tables display as vertically stacked records in the inspector. Test output wraps at a readable size, without a short nested log window. Test summaries keep real pass/fail/skipped counts visible.
- Adjacent arrow navigation uses a 1.55-second eased vertical transition. Advancing moves content and foreground scenery upward while the next scene enters below. Background photographs stay anchored: pages 1–2 and 5–6 share uninterrupted backdrops, while the transitions through pages 2–3–4–5 crossfade with a dark magenta veil. Manual scrolling uses the same picture blend. Two clipped scene views and two background layers provide the visual transition; the backend iframe stays mounted. Larger chapter jumps fade instead of reversing through every scene. Manual scrolling interrupts a transition; reduced-motion preferences skip animation.
- The last arrow stays at Review/export. Back to import remains an explicit action and uses a fade. The existing backend state stays mounted throughout navigation.
- The foreground drone travels completely below the canvas before the analysis robot appears. The slide 5 vehicle and slide 6 robot are removed. The corridor pillars use a separate canvas: they close inward horizontally between 1–2 and 5–6 while other content travels upward. After slide 2, the intro pillars leave upward. Background fades, consent, execution approvals, and backend APIs are retained.
- Workspace typography uses the full scene width supplied over the validated iframe bridge, keeping title and subheading sizes equal across chapters with differently sized content panels. Large headings remain responsive.
- A static pointer halo follows actual pointer events over the scene and embedded controls; it remains visible while the pointer is idle. Clickable controls and evidence cards lift with a shadow on hover, with reduced-motion support. From diamond 2 onward, a black translucent surface sits behind the workspace for contrast.
- Each page now has one full-height scrolling column containing its heading and controls, with Previous/Next fixed outside that scroll area. Opening details expands the workspace to provide more width for both columns. Chapter diamonds have dark translucent backing and larger click targets.
- A newly generated plan opens in the reading pane, with the actual allowed files, proposed changes, priorities, risks, validation strategy, and existing approval confirmation. A persistent Read generated plan button reopens it. Action labels and help text describe imports, demo data, model requests, and approval prerequisites in plain language. Opening a plan never approves or executes it.

Validation: `npm.cmd run lint`, `npm.cmd run build`, and `node scripts/verify_scene.cjs`. Controller checks cover origin/source validation, persistent iframe state, side-inspector messages, arrow timing, manual interruption, reduced motion, long jumps, the final-page stop, and the actual drone drawing path with a recording renderer. These controller tests do not verify React hydration or visual layout. No NVIDIA calls or Docker executions are required for these presentation changes.
